## Deleted Files (Category A)

| File | Reason |
|------|--------|
| `verify_phase1.py` | One-shot manual integration script created to validate Phase 1 (multi-service communication). It starts a live Daphne server, fires HTTP requests, then shuts down — a disposable end-to-end harness, not a repeatable automated test. The automated tests it wraps (`core` test suite) remain intact under `backend/core/tests.py`. |
| `verify_phase2.py` | One-shot manual integration script for Phase 2 (authentication & identity). Same pattern: spawns Daphne, makes real HTTP calls, extracts tokens directly from the database, then exits. The underlying Django test suite (`backend/accounts/tests.py`) covers the same logic as an automated suite. |
| `verify_phase3.py` | One-shot manual integration script for Phase 3 (friends & social networking). Creates live test users via HTTP, manipulates DB state via `manage.py shell`, then verifies social flows. Disposable post-phase validation, not part of the automated test suite. |
| `backend/phase8-playlists.md` | Implementation notes and API specification committed to the `backend/` application root rather than `docs/`. The canonical equivalent (`docs/phase6-music-api.md`, `.agents/tasks/phase8-playlist-report.md`) already exists. This file is a stray draft artifact in the wrong location. |
| `frontend/tsconfig.tsbuildinfo` | TypeScript incremental compiler cache generated by `tsc`. This is a machine-generated binary-like JSON file that changes on every build, should not be committed to version control, and is already conventionally excluded from repos. It carries no source information not derivable from the source files themselves. |

## Borderline Files — Decision Notes

| File | Decision | Rationale |
|------|----------|-----------|
| `verify_phase1.py`, `verify_phase2.py`, `verify_phase3.py` | **Deleted** | These look like test files at first glance, but they are integration harnesses that require a live server and direct DB access — they cannot be run in CI without significant setup. They were phase-completion scripts, not repeatable test suites. All logic they test is covered by the Django unit tests that remain. |
| `backend/phase8-playlists.md` | **Deleted** | The same content exists in both `.agents/tasks/phase8-playlist-report.md` (completion report) and the API docs. Having a duplicate in `backend/` creates confusion about where the authoritative spec lives. The file in `backend/` is the stray copy. |
| `frontend/tsconfig.tsbuildinfo` | **Deleted** | TypeScript compiler output, not source. The `.gitignore` already excludes `build/` and `dist/`; `tsbuildinfo` files fall into the same category of generated output that should not be version-controlled. |
| `.agents/tasks/*.md` | **Preserved** | These are workflow-step completion reports consumed by the agentic task-tracking system. Deleting them would break the workflow's ability to reference prior phase outcomes. |
